# Advanced bot

A forecasting bot for Metaculus bot tournaments, built on `forecasting-tools`
(`AdvancedBot` subclasses `ForecastBot`), plus an evaluation environment to prove which parts actually help.
The simple bots (`main.py`, `geo_forecaster.py`) are untouched. Arabic guide: [ADVANCED_BOT_AR.md](../ADVANCED_BOT_AR.md).

**Safety defaults:** nothing is published (`publish_to_metaculus: false` + an explicit `--publish` flag are both
required) and no workflow runs on a schedule.

## Pipeline

```
question ─► Researcher agent (4–6 tool rounds: AskNews · Exa web · Wikipedia-as-of-date · [FutureSearch MCP])
              lookback window = clamp(2 × days-to-resolution, 30, 365) days, ENDING at the cutoff
              fixed template, every claim cites [n], sources list generated by code, no forecasting
         ─► Summary (cheaper model, 2 paragraphs + sources)
         ─► N forecasters in parallel, round-robin over model families
              draft ((a)–(h) template or simple) ─► checks ─► [critic ─► response] × rounds
         ─► aggregation (weighted log-odds + extremizing / mean / median; weighted quantile mean)
         ─► Metaculus format (binary p · MC ≥1% each, sum 100% · 15 increasing percentiles within bounds)
```

Checks done **in code**, not by the model:

| Check | What happens |
|---|---|
| Format | strict per-type validation; the error is sent back to the model (`max_format_retries`), last resort repair for percentiles |
| Arithmetic | "A of B (P%)", "A + B = C", "from A to B (±P%)", "N times in M years (P% per year)" are recomputed; corrections are given to the forecaster and critic |
| Unverified facts | figures and proper names in forecaster/critic text that appear nowhere in the research are listed as UNVERIFIED (not to be built on); `verification: verify` runs a quick date-bounded search + verifier instead |
| Consistency | forecaster states `evidence_direction` vs its base rate / status quo and `update_direction` in critique rounds; a contradiction triggers one clarification request |
| Time leakage | every tool is bounded to the cutoff; results dated after it are dropped in code |

Section 3 mixture tool: with `mixture.numeric: true` the forecaster gives 1–4 scenarios
(normal / lognormal / student-t, weight, params) instead of percentiles; code computes the CDF, truncates at
closed bounds and reads off the 15 percentiles. With `mixture.binary_time_to_event: true`, binary questions get
a time-to-event mixture + `p_never`, and P(yes) = P(event before the resolution date). The scenarios are
returned as a structured JSON answer (portable across all models) rather than a function-calling API.

## Files

| File | Purpose |
|---|---|
| `configs/default.yaml` | **the** settings file (models, forecasters, critique rounds, research limits, aggregation, checks) |
| `configs/ensemble.yaml` | section 2: 4 families × 2 samples |
| `configs/ablations/*.yaml` | section 4/5 experiment configs (`extends:` default, override only what changes) |
| `researcher.py`, `tools.py` | research agent + date-bounded tools |
| `forecasters.py`, `checks.py`, `mixture.py`, `aggregation.py`, `pipeline.py` | forecasting stages |
| `bot.py` | `AdvancedBot(ForecastBot)` + per-question log (`logs/advanced/<date>/<id>.md/.json`: cost by model, time, models used, members, warnings, full Markdown, Arabic summary) |
| `eval/` | data collection, frozen research, leak check, metrics, compare, ablations, ensemble, RL export |
| `testing/` | offline fake backend + synthetic questions (tests only) |

## Keys (environment variables / GitHub Secrets — never in code)

`OPENROUTER_API_KEY` (models), `ASKNEWS_CLIENT_ID` + `ASKNEWS_SECRET`, `EXA_API_KEY`,
`METACULUS_TOKEN` (reading questions, collecting eval data, publishing), optional `FUTURESEARCH_API_KEY`.
Missing search keys simply disable that tool (with a warning).

## Running

```bash
poetry install
python run_advanced.py --mode custom --question-file questions/example_question.json   # never published
python run_advanced.py --mode urls --url https://www.metaculus.com/questions/12345/    # dry run
python run_advanced.py --mode tournament                                                # dry run
python run_advanced.py --mode tournament --publish     # only if publish_to_metaculus: true in the config
```

GitHub: **Actions → Advanced bot (manual)**, or **Geopolitical forecast (manual)** with `bot: advanced`.
To schedule later, uncomment the `schedule:` lines in `.github/workflows/advanced_bot.yaml`.

## Evaluation (do this before trusting any change)

```bash
python eval.py collect --n 300                 # resolved questions from past AIB tournaments + MiniBench
python eval.py research --limit 20             # start small; frozen research cut at each question's open time
python eval.py score                           # Brier, log loss, CRPS, pinball, Metaculus baseline, calibration
python eval.py --config no_critic --config default   # paired bootstrap CI of the difference
python eval.py ablate                          # section 4 -> eval_runs/ablation_report.md + recommended.yaml
python eval.py ensemble --config ensemble      # section 2: CV-fitted weights, extremizing, correlations, LOO
python eval.py research-sets                   # section 5: AskNews only vs FutureSearch vs both
python eval.py export-rl                       # section 6: JSONL (research, prompt, output, outcome, reward)
```

How it saves money and stays fair:
- research is computed **once** per question and research set, then reused by every config;
- stored forecasts are keyed by what affects the LLM calls, so configs that differ only in aggregation, or
  in the number of forecasters, share them (a 5-forecaster run contains the 1- and 3-forecaster runs);
- every command that spends shows the amount of work first and asks (or needs `--yes`).

Known limits of back-testing, stated plainly:
- **Model knowledge:** a model trained after a question resolved may simply know the answer. Prefer questions
  that resolved after your models' training cutoffs (the default tournaments are fall 2025 / spring 2026).
- **Leak judge:** an LLM judge, not a guarantee; together with the date filters it removes most leaks.
  FutureSearch results carry no publication-date filter unless you configure one.
- **Significance:** with < 200 questions most ablations come out "no significant difference";
  that verdict means "not proven", not "proven useless".
- **Costs:** LiteLLM cost estimates cover LLM calls only (not AskNews/Exa/FutureSearch).

## Tests (offline, no keys)

```bash
python -m unittest discover tests -v
python run_advanced.py --mode custom --question-file questions/example_question.json --fake
python eval.py demo-data --data-dir eval_demo --fake && python eval.py ablate --data-dir eval_demo --runs-dir eval_demo/runs --fake
```
The fake backend peeks at known answers to exercise the scoring code; its numbers mean nothing.
